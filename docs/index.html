FOUND DAY ONE

A live typosquat of the official MCP filesystem server

While building test fixtures I invented a plausible fake package name. It turned out to be real, and it is on npm right now.

@modelcontextprotoco1/server-filesystem  ← digit one
@modelcontextprotocol/server-filesystem  ← lowercase L

The impersonation is byte-identical to official release 2026.1.14. Every file in dist/ has the same SHA-256 as the real thing. The entire difference is one character in the name:

- "name": "@modelcontextprotocol/server-filesystem"
+ "name": "@modelcontextprotoco1/server-filesystem"

It ships forged provenance too — author: "Anthropic, PBC", the official homepage, and a repository field pointing at the real GitHub repo. Published 2026-04-13. It does not appear in npm search results.

There is no malicious code in it today. That is the point. This is the setup phase of a rug pull: publish something clean and identical, wait for installs to accumulate, then ship a payload in a later version — which every npx user and every unpinned config picks up automatically, with no review.

A content scanner cannot catch this. There is nothing bad in the content; the content is the official code. Only provenance catches it.

Why another scanner

Independent testing put YARA-style MCP scanners at roughly a 78% false-positive rate. A tool that is wrong four times in five gets uninstalled within a week — and then you have no scanner at all.

mcpaudit optimises for precision instead of recall:

  • Every finding cites its evidence. The exact env var, the exact argument, the exact line.
  • Findings carry a confidence tier. Low-confidence guesses stay hidden unless you ask for them.
  • Checks are context-aware. A filesystem server touching the filesystem is not a finding — its scope is. Flagging the former is exactly the noise that gets scanners deleted.
  • Trusted publishers score differently. An unpinned official package is LOW. An unpinned unknown one is MEDIUM.

Usage

npx github:AndrewXuTurtle/mcpaudit                 # scan every MCP config on this machine
npx github:AndrewXuTurtle/mcpaudit --deep          # also download and read each package source
npx github:AndrewXuTurtle/mcpaudit --paranoid      # include lower-confidence findings
npx github:AndrewXuTurtle/mcpaudit --markdown -o audit.md
npx github:AndrewXuTurtle/mcpaudit --fail-on critical   # for CI

Configs are discovered automatically for Claude Desktop, Claude Code, Cursor, Windsurf, VS Code, and any .mcp.json in the working directory.

Design notes

Zero runtime dependencies

A security scanner that pulls in forty transitive packages is its own supply-chain risk. mcpaudit uses only the Node standard library — including a small hand-written tar reader, because taking a dependency in order to audit dependencies is not a trade worth making.

Nothing is executed

--deep downloads the tarball from the registry and reads it in memory. The server is never started and the package is never installed. Auditing an untrusted server by running it is not auditing.

Secrets are never printed

Detected credentials are redacted to a prefix, a suffix, and a length.
